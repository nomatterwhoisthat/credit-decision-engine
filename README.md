# Кредитный скоринг: от вероятности дефолта до решения «одобрить или отказать»

## Задача

Клиент подаёт заявку на кредитную карту. Банку нужно решить, одобрять её или нет. Для этого нужны две вещи. Первая это оценка вероятности, что клиент перестанет платить (PD, probability of default). Вторая это правило, которое по этой вероятности и по деньгам, которые банк может заработать или потерять, выдаёт решение.

В проекте собраны обе части на открытых данных. Порядок такой же, как в банковских рисках: данные, модели PD, стратегия решений, мониторинг.

## Зачем это сделано

Показать полный путь, а не одну модель. Обычно в учебных проектах останавливаются на метрике AUC. Здесь после модели считается, сколько денег приносит решение, насколько этот вывод зависит от допущений и как следить за моделью после запуска.

## Откуда данные

Набор Default of Credit Card Clients (UCI, на OpenML id 42477). Это 30 000 клиентов одного банка на Тайване за 2005 год. По каждому известны кредитный лимит, возраст, образование и шесть месяцев истории: статус платежа, сумма счёта, сумма платежа. Нужно предсказать, просрочит ли клиент платёж в следующем месяце. Просрочили 22,1 % клиентов.

Данные скачиваются сами при первом запуске. Руками ничего загружать не надо.

## Что сделано

| Блок | Что именно | Файл |
|---|---|---|
| Признаки | 39 признаков из истории за 6 месяцев. Число месяцев с просрочкой, самая длинная серия просрочек, динамика просрочек, доля использованного лимита, какую часть счёта клиент гасит, разброс счетов | `src/features.py` |
| Скоркарта | Классическая банковская модель. Признаки разбиваются на интервалы, считается WoE и IV, потом логистическая регрессия. Признаки с неверным знаком коэффициента или p-value выше 0,05 убираются. Остаётся 14 признаков и константа | `src/woe_scorecard.py` |
| Бустинг | CatBoost (подбор параметров в Optuna, 12 попыток) и LightGBM | `src/pipeline.py` |
| Калибровка | Проверка, что предсказанная вероятность совпадает с реальной долей дефолтов. Метрики Brier, ECE, тест Хосмера-Лемешова | `src/metrics.py` |
| Объяснения | SHAP для CatBoost | `results/shap_summary.png` |
| Стратегия | Для каждого клиента считается ожидаемая прибыль. Решение одобрить принимается, если она положительна. Результат проверяется на отложенной выборке по реальным исходам | `src/strategy.py` |
| Мониторинг | PSI по признакам и по скору, имитация экономического шока, поиск аномальных заявок (Isolation Forest) | `src/monitoring.py` |
| Проверка на дискриминацию | SEX и MARRIAGE в моделях не используются. После обучения сравнивается доля одобрений по полу и возрасту | `run_all.py` |
| PySpark | Часть признаков переписана на Spark. Тест проверяет, что значения совпадают с pandas | `src/spark_features.py` |

Данные делятся на три части в пропорции 60 / 20 / 20. Обучение, валидация (подбор параметров и калибровка), тест (все цифры ниже).

## Результаты

### Качество моделей на тесте (6 000 клиентов)

| Модель | AUC | Gini | KS | Brier | ECE |
|---|---|---|---|---|---|
| Скоркарта (14 признаков) | 0,777 | 0,554 | 0,420 | 0,1354 | 0,014 |
| LightGBM | 0,793 | 0,587 | 0,454 | 0,1309 | 0,009 |
| CatBoost | 0,792 | 0,584 | 0,453 | 0,1314 | 0,010 |

Бустинг лучше скоркарты примерно на 3 пункта Gini. Скоркарта отстаёт немного, при этом её можно целиком объяснить регулятору, поэтому в банках её держат как запасную модель.

Калибровка (изотоническая регрессия на валидации) не помогла. Вероятности бустинга и так близки к реальным, ECE около 0,01. После калибровки у CatBoost ECE вырос с 0,0100 до 0,0115. В таблице стоят значения без калибровки. Версии с калибровкой лежат в `results/model_metrics.csv`.

### Стратегия решений

Допущения заданы в классе `Economics` и меняются в одну строку. Доход банка 22 % от средней использованной части лимита. Потери при дефолте (LGD) 60 %. Доля лимита, которая будет использована к моменту дефолта (CCF), 75 %. Минимальная доля использования лимита для расчёта дохода 10 %.

Клиент одобряется, если `(1 − PD) × доход > PD × потери`. Порог PD получается свой у каждого клиента. У клиентов, которые почти не пользуются картой, доход маленький, а риск по всему лимиту остаётся. Поэтому порог для них ниже.

| Стратегия | Доля одобрений | Доля дефолтов среди одобренных | Реальная прибыль на тесте, млн (95 % доверительный интервал) |
|---|---|---|---|
| Одобрять всех | 100 % | 22,1 % | −27,2 (от −32,9 до −20,8) |
| Простой порог по PD с той же долей одобрений | 40,5 % | 7,6 % | 14,5 (от 11,2 до 17,9) |
| **Ожидаемая прибыль, PD от CatBoost** | 40,5 % | 10,4 % | **21,5 (от 18,3 до 24,6)** |
| Ожидаемая прибыль, PD от скоркарты | 35,7 % | 11,1 % | 21,4 (от 18,3 до 24,3) |
| Идеальный вариант (заранее известно, кто не заплатит) | 77,9 % | 0 % | 51,8 |

При одинаковой доле одобрений правило по ожидаемой прибыли даёт примерно на 7 млн больше, чем простой порог. Оно берёт чуть более рискованных клиентов, которые приносят больше дохода, и отказывает надёжным, но невыгодным. Деньги указаны в тайваньских долларах (NT$).

Этот вывод проверен на 9 сочетаниях допущений (LGD 0,4 / 0,6 / 0,8 и доход 15 / 22 / 30 %). Правило по прибыли выигрывает у простого порога во всех девяти случаях. Таблица в `results/sensitivity.csv`.

Ожидаемые потери на 12 месяцев (PD × LGD × EAD) по одобренным клиентам теста составляют 14,1 млн. По всей тестовой выборке 78,8 млн.

### Мониторинг

PSI всех признаков между обучением и тестом не выше 0,004. Для случайного разбиения это ожидаемо.

Дальше смоделирован шок. В нём у клиентов больше просрочек, выше счета и ниже платежи. Этот сценарий придуман для проверки мониторинга, реальных данных за ним нет. В нём 10 признаков получили PSI выше 0,25, а PSI скора вырос до 0,14. Средняя предсказанная вероятность дефолта выросла с 22,3 % до 25,4 %. Isolation Forest отметил 1,1 % обычных заявок и 1,6 % заявок в сценарии шока.

### Проверка на дискриминацию

Доля одобрений для SEX = 1 составляет 43,0 %, для SEX = 2 38,9 %. Отношение 0,91. По возрастным группам доля одобрений от 37,9 % до 42,3 %. Реальная доля дефолтов в группах тоже отличается, поэтому разница в одобрениях сама по себе не доказывает несправедливость. И обратно, проверка не доказывает, что косвенных признаков пола в данных нет.

## Ограничения

- В данных только клиенты, которых банк уже одобрил. Тех, кому отказали, в выборке нет. Поэтому прибыль на тесте годится для сравнения стратегий между собой, а не как прогноз прибыли банка.
- Доход, LGD и CCF взяты как допущения, на данных они не оценивались.
- В данных нет дат. Проверки на более поздних периодах нет, использовано случайное разбиение.
- Вероятность дефолта считается не зависящей от размера лимита, поэтому подбор лимита не делался.

## Как запустить

```bash
pip install -r requirements.txt
python run_all.py       # около минуты на 2 ядрах, создаёт папки results/ и artifacts/
pytest tests/           # тесты метрик, стратегии, признаков и сравнение Spark с pandas
```

Тест со Spark (`tests/test_spark_parity.py`) требует Java и pyspark. Если pyspark не установился, запускать `pytest tests/test_core.py`. На Python 3.13 pyspark собирается с ошибкой, на Python 3.12 установился.

## Структура

```
src/            код (признаки, модели, стратегия, мониторинг, Spark)
tests/          тесты
results/        таблицы и графики, которые создаёт run_all.py
artifacts/      обученный CatBoost и калибровщик, используются в проекте credit-policy-agent
run_all.py      запускает всё и пересоздаёт results/
```
